Room Database: Từ Nền Tảng Đến Kiến Trúc Senior

Toàn diện về SQLite Type Affinity, @TypeConverter, chuẩn hóa bảng 1-N, WAL Concurrency, InvalidationTracker, tối ưu truy vấn và Migration Production.

1. Nền Tảng SQLite & Hệ Thống Kiểu Dữ Liệu

SQLite dùng cơ chế Dynamic Typing (Type Affinity): kiểu dữ liệu gắn với giá trị thực tế được lưu, không cố định vào cột như PostgreSQL hay MySQL.

Kiểu SQLite Bản chất kỹ thuật Ánh xạ Kotlin mặc định Lưu ý thực tế khi thiết kế Schema
NULL Giá trị rỗng / không tồn tại null (String?, Int?) Chiếm ít dung lượng nhất. Trong mệnh đề so sánh: NULL = NULL luôn trả về false.
INTEGER Số nguyên có dấu, tự co giãn 1, 2, 3, 4, 6 đến 8 bytes Byte, Short, Int, Long, Boolean Tiết kiệm bộ nhớ tối đa. Ví dụ số 5 chỉ tốn 1 byte lưu trữ dù được định nghĩa là 64-bit.
REAL Số thực dấu phẩy động 8-byte IEEE Float, Double Thích hợp cho tọa độ GPS, chỉ số vật lý. Không dùng lưu tiền tệ do sai số float (nên dùng Long cents).
TEXT Chuỗi ký tự mã hóa UTF-8, UTF-16 String, Char Không giới hạn độ dài cố định như VARCHAR(255). Giới hạn mặc định lên đến 1GB.
BLOB Binary Large Object (chuỗi bytes nhị phân) ByteArray Lưu vector nhị phân, dữ liệu mã hóa. Tránh lưu ảnh lớn (> 1–2MB) trực tiếp để tránh nghẽn CursorWindow.

2. Chuyển Đổi Dữ Liệu Với @TypeConverter

Bản chất của @TypeConverter không chỉ giới hạn ở String ↔ TEXT, mà là cung cấp cặp hàm 2 chiều để chuyển đổi một kiểu dữ liệu Kotlin phức tạp thành một trong 5 kiểu SQLite hiểu được và ngược lại.

import androidx.room.TypeConverter
import kotlinx.serialization.encodeToString
import kotlinx.serialization.json.Json
import java.time.Instant

class AppTypeConverters {

    // 1. Instant <-> Long (INTEGER epoch milliseconds)
    @TypeConverter
    fun fromInstant(instant: Instant?): Long? = instant?.toEpochMilli()

    @TypeConverter
    fun toInstant(millis: Long?): Instant? = millis?.let { Instant.ofEpochMilli(it) }

    // 2. List <-> JSON String (TEXT)
    @TypeConverter
    fun fromStringList(tags: List?): String? = tags?.let { Json.encodeToString(it) }

    @TypeConverter
    fun toStringList(jsonString: String?): List? = 
        jsonString?.let { Json.decodeFromString>(it) }
}

3. Chuẩn Hóa Quan Hệ 1-N (One-to-Many) Thay Thế JSON

Lưu danh sách dạng chuỗi JSON khiến truy vấn tìm kiếm WHERE tag = ? rơi vào $O(N)$ (Full Table Scan). Chuẩn hóa sang quan hệ 1-N giúp đạt tốc độ truy vấn $O(\log N)$ nhờ B-Tree Index và đảm bảo toàn vẹn dữ liệu qua CASCADE.

// Bảng Cha: notes (1)
@Entity(tableName = "notes")
data class NoteEntity(
    @PrimaryKey(autoGenerate = true)
    @ColumnInfo(name = "note_id")
    val noteId: Long = 0,
    val title: String,
    val content: String
)

// Bảng Con: tags (N)
@Entity(
    tableName = "tags",
    foreignKeys = [
        ForeignKey(
            entity = NoteEntity::class,
            parentColumns = ["note_id"],
            childColumns = ["note_id"],
            onDelete = ForeignKey.CASCADE // Xóa ghi chú tự động xóa toàn bộ tags liên quan
        )
    ],
    indices = [
        Index(value = ["note_id"]),  // Tối ưu truy vấn JOIN
        Index(value = ["tag_name"]) // Tối ưu tìm kiếm theo tag
    ]
)
data class TagEntity(
    @PrimaryKey(autoGenerate = true)
    @ColumnInfo(name = "tag_id")
    val tagId: Long = 0,
    @ColumnInfo(name = "note_id")
    val noteId: Long,
    @ColumnInfo(name = "tag_name")
    val tagName: String
)

Tạo DTO trung gian và DAO với @Transaction:

data class NoteWithTags(
    @Embedded val note: NoteEntity,
    @Relation(
        parentColumn = "note_id",
        entityColumn = "note_id"
    )
    val tags: List
)

@Dao
interface NoteDao {
    @Insert(onConflict = OnConflictStrategy.REPLACE)
    suspend fun insertNote(note: NoteEntity): Long

    @Insert(onConflict = OnConflictStrategy.REPLACE)
    suspend fun insertTags(tags: List)

    @Transaction
    suspend fun insertNoteWithTags(note: NoteEntity, tags: List) {
        val noteId = insertNote(note)
        val tagEntities = tags.map { TagEntity(noteId = noteId, tagName = it) }
        insertTags(tagEntities)
    }

    // Bắt buộc dùng @Transaction khi query Relation để tránh Dirty Read
    @Transaction
    @Query("SELECT * FROM notes")
    fun getNotesWithTags(): Flow>

    // Tìm kiếm tốc độ cao O(log N) với Index
    @Transaction
    @Query("""
        SELECT * FROM notes 
        INNER JOIN tags ON notes.note_id = tags.note_id 
        WHERE tags.tag_name = :tagQuery
    """)
    fun getNotesByTag(tagQuery: String): Flow>
}

4. Concurrency & Tối Ưu Quản Lý Dữ Liệu Tầng Thấp

  • Cơ chế InvalidationTracker: Room tạo bảng ngầm room_table_modification_log và gắn triggers (INSERT, UPDATE, DELETE) lên các bảng quan sát. Khi dữ liệu đổi, tracker trên background thread phát hiện và kích hoạt re-query cho các luồng Flow<T>.
  • WAL (Write-Ahead Logging) vs Rollback Journal:
    • Rollback Journal: Tạo bản sao trang cũ vào journal file khi ghi. Khóa toàn bộ database (Read chặn Write, Write chặn Read).
    • WAL Mode (Mặc định từ Android 9): Thao tác ghi được nối vào file -wal riêng biệt. Cho phép 1 Writer hoạt động song song với nhiều Reader mà không gây nghẽn.
  • ACID & Transactions: Đảm bảo tính Nguyên tử (Atomicity), Nhất quán (Consistency), Cô lập (Isolation) và Bền bỉ (Durability). Dùng khi cập nhật nhiều bảng liên quan, xử lý batch insert hàng loạt và bọc các truy vấn @Relation.

5. Chiến Lược Migration An Toàn Trên Production

Chiến lược Cơ chế Trường hợp áp dụng
Destructive Migration Xóa sạch file database cũ và tạo lại từ đầu. Giai đoạn dev, testing hoặc dữ liệu chỉ là cache tạm từ API.
Auto Migration Dùng @AutoMigration, Room đối chiếu file schema JSON để tự sinh script. Thêm bảng mới, thêm cột có giá trị mặc định hoặc cho phép null.
Manual Migration Tự viết SQL thô qua Migration(from, to). Đổi kiểu cột, tách/gộp bảng, di chuyển dữ liệu phức tạp.

Quy trình 4 bước an toàn trên Production:

  1. Export Schema: Bật room.schemaLocation trong Gradle để kiểm soát lịch sử schema qua file JSON.
  2. Xử lý giới hạn SQLite (Migration 4 bước): Tạo bảng tạm mới → Chép dữ liệu từ bảng cũ sang → Xóa bảng cũ → Đổi tên bảng tạm thành bảng chính.
  3. Hỗ trợ nhảy cóc phiên bản: Định nghĩa chuỗi migration tuần tự (1 -> 2, 2 -> 3) để người dùng cập nhật từ bản bất kỳ không bị crash IllegalStateException.
  4. Kiểm thử tự động: Sử dụng MigrationTestHelper để kiểm tra tính toàn vẹn của dữ liệu trước khi phát hành bản cập nhật.

6. Tích Hợp Chuẩn Clean Architecture

  • Phân tách Model: Không truyền trực tiếp @Entity lên Domain Layer hoặc Compose UI. Luôn dùng mapper (Entity.toDomain()) chuyển đổi sang Domain Model.
  • Single Source of Truth (SSOT): Repository điều phối: Kéo dữ liệu từ API → Lưu vào Room Database → Phát luồng Flow<DomainModel> từ Room lên ViewModel.
  • Dependency Injection: Cung cấp RoomDatabase dưới dạng @Singleton bằng Hilt, chỉ inject interface DAO vào Repository Implementation.
Architecture

Clean Architecture & Mô Hình MVI

Tách biệt rõ ràng giữa Business Logic và UI Framework, đảm bảo khả năng Test và bảo trì lâu dài.

1. Kiến Trúc 3 Tầng Chuẩn Android

  • Presentation Layer: Jetpack Compose UI, ViewModels, States, Side Effects.
  • Domain Layer: Use Cases, Business Models, Repository Interfaces (Pure Kotlin, không phụ thuộc Android Framework).
  • Data Layer: Repository Implementations, Room Entities/DAOs, Retrofit API Services, DataSources.

2. Triển Khai MVI (Model-View-Intent)

MVI áp dụng dòng dữ liệu một chiều (Unidirectional Data Flow - UDF):

// 1. UI State (Immutable)
data class NoteUiState(
    val isLoading: Boolean = false,
    val notes: List = emptyList(),
    val errorMessage: String? = null
)

// 2. User Intent / Action
sealed interface NoteIntent {
    data class SearchQuery(val query: String) : NoteIntent
    data class DeleteNote(val noteId: Long) : NoteIntent
    object Refresh : NoteIntent
}

// 3. Side Effect (Chỉ bắn 1 lần: Toast, Navigation)
sealed interface NoteEffect {
    data class ShowToast(val message: String) : NoteEffect
    data class NavigateToDetail(val noteId: Long) : NoteEffect
}
Concurrency

Kotlin Coroutines & Reactive Flow

Quản lý Concurrency bất đồng bộ an toàn và xử lý luồng dữ liệu liên tục.

1. Structured Concurrency

Đảm bảo không rò rỉ tác vụ ngầm (Coroutine leaks) thông qua CoroutineScope và vòng đời (LifecycleScope, ViewModelScope).

  • Dispatchers.Main: Cập nhật UI.
  • Dispatchers.IO: Truy vấn mạng, ghi đọc file, Database.
  • Dispatchers.Default: Xử lý thuật toán nặng, parse JSON lớn, mã hóa.

2. StateFlow vs SharedFlow

Tiêu chí StateFlow SharedFlow
Mục đích Lưu trữ và phát trạng thái UI (State) Bắn sự kiện một lần (Events, Side Effects)
Giá trị ban đầu Bắt buộc có (Initial Value) Không bắt buộc
Replay Cache Mặc định giữ 1 giá trị gần nhất Tùy biến cấu hình (0, 1 hoặc N)
Modern UI

Jetpack Compose: Recomposition & Tối Ưu

Bộ công cụ dựng giao diện khai báo hiện đại, hiệu năng cao trên Android.

1. Quy Tắc Recomposition Bỏ Qua (Smart Recomposition)

Compose chỉ recompose những hàm Composable có tham số đầu vào bị thay đổi. Để Composable đạt trạng thái có thể bỏ qua (Skippable), toàn bộ kiểu dữ liệu truyền vào phải được trình biên dịch nhận diện là Stable.

2. Đánh Dấu @Stable và @Immutable

import androidx.compose.runtime.Immutable

@Immutable
data class UserUiModel(
    val id: String,
    val name: String,
    val avatarUrl: String
)

Sử dụng remember với key chính xác và hạn chế tạo lambda object mới bên trong vòng lặp render list.

Media & Streaming

HLS Streaming & Media3 ExoPlayer

Kiến trúc truyền phát video trực tuyến thích ứng băng thông (Adaptive Bitrate Streaming) trên thiết bị di động.

1. Giao Thức HTTP Live Streaming (HLS) Là Gì?

HLS do Apple phát triển, hoạt động trên giao thức HTTP tiêu chuẩn. Cơ chế cốt lõi là chia nhỏ video thành các đoạn ngắn (segment thường từ 2 - 6 giây, định dạng .ts hoặc .m4s) và được lập chỉ mục bởi các file playlist định dạng .m3u8.

2. Phân Biệt Master Playlist và Media Playlist

  • Master Playlist: Chứa danh sách các biến thể phân giải (1080p, 720p, 480p) kèm theo thông số băng thông (bitrate, codecs). Player dùng file này để chuyển đổi chất lượng thích ứng (ABR).
  • Media Playlist: Danh sách địa chỉ URL của từng phân đoạn video thực tế (chunk file) kèm thời lượng cụ thể.

3. Tích Hợp Android Media3 ExoPlayer

import androidx.media3.common.MediaItem
import androidx.media3.common.MimeTypes
import androidx.media3.exoplayer.ExoPlayer

// Khởi tạo ExoPlayer chuẩn HLS
val player = ExoPlayer.Builder(context).build().apply {
    val mediaItem = MediaItem.Builder()
        .setUri("https://example.com/live/master.m3u8")
        .setMimeType(MimeTypes.APPLICATION_M3U8) // Chỉ định chuẩn HLS
        .build()
    
    setMediaItem(mediaItem)
    prepare()
    playWhenReady = true
}

Luôn giải phóng tài nguyên trong Lifecycle (player.release()) để tránh rò rỉ bộ nhớ codec phần cứng.
